RAILWAY DEPLOYMENT

Published service:
  https://modis-viirs-harmonization-production.up.railway.app

railway.json builds deploy/series.Dockerfile from main. The service hosts
historical series, regional queries, experimental forecasts and the API viewer.
It does not deploy the separate PostgreSQL-backed events API.

The image restores SQLite from versioned compressed data and verifies SHA-256
and SQLite integrity. Runtime uses a non-root account. The service needs no
Earthdata, FIRMS or Google Maps credentials. Public GET requests allow CORS.

For a new Railway service:
  New Project > Deploy from GitHub repo > select repository and main branch.
  Once healthy, open Settings > Networking > Generate Domain.
Use the actual domain from the dashboard; do not infer it from a service name.

Verify deployment:
  python deploy/verify_public.py https://YOUR_ACTUAL_DOMAIN
  python deploy/verify_public.py https://YOUR_ACTUAL_DOMAIN --require-risk
  python deploy/verify_validation_web.py https://YOUR_ACTUAL_DOMAIN

Local Docker:
  docker build -f deploy/series.Dockerfile -t modis-viirs-series .
  docker run --rm -p 8000:8000 modis-viirs-series

The health route verifies the published historical snapshot independently of
the optional legacy database. Forecast validity must be checked through its
metadata; a running service does not make an expired forecast current.

The separate Netlify application lives in fuegotrazo/. Its build configuration
does not change the API's Docker allowlist. Review automatic-deployment settings
and available hosting resources in the service dashboard.

Reference: https://docs.railway.com/reference/config-as-code
